# VEC1 electron substrate (8.1.0)

The VEC1 Electron Substitute candidate (`VEC1_ES 0.1.1-candidate`) is applied to this browser
under `substrate/`. It is a **classical virtual-electron control plane**: identity, sealed
state, snapshot/clone, lifecycle and hash-chained evidence. It is not a physical-electron
simulator, not a QPU, and not the Chromium/Node desktop framework that shares the name.

## What it replaces

The browser already had no Electron: DF_Medium is the web engine and WPF is a pixel presenter.
What was still unrepresented was the part an Electron-class framework actually owns — the
**application lifecycle**: the app object, its windows, its per-view processes and the state
that belongs to each. 8.1.0 gives that to VEC1.

| Electron-class responsibility | VEC1 representation |
|---|---|
| app instance and its lifetime | one **session electron**, `GENESIS` at launch, `RETIRE` at exit |
| renderer process per view | one **tab electron**, forked from a sealed session snapshot |
| spawning a view | `fork` -> freeze, canonical snapshot, sealed hash, child lineage record |
| per-view state | canonical VEC electron state, hashed on every write |
| what the view did | `PRESENTATION` / `PRESENTATION_FAILED` ledger events |
| closing a view | `RETIRE` — terminal and monotonic, never rolled back |

## Architecture

```
JA21 Omni Bin presenter (host/Vec1Substrate.cs, C#)
    writes sealed electron state + hash-chained ledgers
        substrate/runtime/state/electrons/<id>/state.json
        substrate/runtime/state/electrons/<id>/ledger.jsonl
        substrate/runtime/state/snapshots/<hash>.json
            |
            |  same canonical format, no shared process
            v
VEC1 control plane (substrate/vec1, Python)
    vecctl presenter-audit   re-derives every hash and chain
    vecctl audit             the same for vecctl-owned electrons
    vecctl nodes             how each VEC node binds in this package
    vecctl verify [--full]   strict four-node fabric proof (fail-closed)
```

The two halves never share memory and never trust each other. The presenter writes; the
control plane independently re-derives. Both take the same byte-range lock on
`substrate/runtime/state/.vec1.lock`, so a running browser and a concurrent `vecctl`
cannot interleave a write.

### Canonical-format conformance

Both halves must produce identical canonical JSON or every hash would be wrong in good faith.
`substrate/evidence/presenter/CANONICAL_VECTORS.json` holds golden vectors generated by the
Python side and covering key ordering, control-character escapes, non-BMP text, nesting and a
full electron shape. The presenter verifies itself against that file **at startup** and refuses
to seal anything if it disagrees; `substrate/tests/test_presenter_format.py` verifies the file
against the control plane.

## Node binding

`substrate/NODES.json` binds each VEC node to a container already in this package instead of
duplicating multi-megabyte trees:

| Node | Container | Status |
|---|---|---|
| `N_SMALL` | `helper/DF_Small` | bound (byte-pinned helper capsule) |
| `N_MEDIUM` | `engine/df_medium/baseline` | bound (web-engine node baseline) |
| `N_LARGE` | — | **not vendored in this package** |
| `N_XLARGE` | — | **not vendored in this package** |

`vec1/binding.py` turns that map into the `DF_<NODE>_ROOT` overrides the DF_Fabric adapter
already honours, so nothing in DF_Fabric was forked to make this work.

### Why strict execution reports BLOCKED

VEC1's execution policy requires **all four** nodes to bind, the same sealed PA-LCTL rows to
run across the fabric, a `CROSS_NODE_DIFFERENTIAL_AGREEMENT` verdict, and a passing event-log
replay. Two nodes are absent here, so that gate cannot be reached, and the honest result is
`BLOCKED` (exit code 3) rather than a relaxed profile that would look like a pass.

To lift it, copy `DF_Large` and `DF_Xtra_Large` from the VEC1_ES package into `substrate/`
and set their `container` values in `NODES.json`. `vecctl nodes` prints the exact instruction.

## Claim discipline

This is the part worth reading twice. A presenter electron:

* **never** records a fabric execution event and never carries a fabric verdict;
* uses a closed event vocabulary (`GENESIS`, `CLONE_GENESIS`, `FORK`, `SNAPSHOT`,
  `PRESENTATION`, `PRESENTATION_FAILED`, `SUSPEND`, `RESUME`, `RETIRE`, `RESTORE`);
* is rejected by `vecctl presenter-audit` if any ledger event steps outside it.

Rendering a page is a presentation, not cross-node differential agreement. The integration is
deliberately built so the presenter *cannot* blur that line, and the package verifier fails if
the source ever gains the ability to.

## Failure behaviour

The substrate never blocks browsing, and never pretends to be running when it is not:

| Verdict | Meaning | Presenter behaviour |
|---|---|---|
| `BOUND` | config sealed, policy fail-closed, canonical self-test passed | seals session and tab electrons |
| `DEGRADED` | sealing started but a write or quota failed | stops sealing, states the reason in the trust line |
| `BLOCKED` | substrate absent, policy relaxed, or self-test failed | seals nothing, says so |

The verdict is on the trust line at the bottom right of the window, in full on its tooltip, and
in the drawer's first section.

## Operating it

```
Verify VEC1 Substrate.cmd                     node binding + control-plane suite
Audit VEC1 Electrons.cmd                      re-derive every presenter-written hash and chain
python substrate\vec1\vecctl.py nodes         how each node binds here
python substrate\vec1\vecctl.py presenter-audit
python substrate\vec1\vecctl.py presenter-gc  retire electrons left by an unclean exit
python substrate\vec1\vecctl.py verify --full strict fabric proof (BLOCKED in this package)
python tools\vec_seal.py                      reseal after editing the substrate config
```

Exit codes: `0` ok, `1` fail, `2` usage, `3` blocked, `4` integrity failure, `5` policy refusal.

## Boundaries this integration does not cross

* No network transport is added. The substrate's own policy is `network: deny`.
* The substrate writes only below `substrate/runtime/`.
* The presenter never mutates a `vecctl`-owned electron, and `vecctl` never mutates a
  presenter-owned electron's runtime.
* Closure of the source VEC1 package's 286,440 checklist items is **not** claimed, here or
  anywhere else in this package. `substrate/evidence/components/` keeps those records.
