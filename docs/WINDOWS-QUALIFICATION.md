# Windows qualification checklist — 9.0.0 JA21 Optical Instrument

1. Extract the shallow Windows-safe outer ZIP and run `INSTALL.cmd`. Confirm installation reports 9.0.0 complete and creates the **JA21 Virtual Browser** Desktop icon plus **Start Menu → JA21** shortcut using `assets\vb.ico`.
2. Launch the installed `Verify JA21 Virtual Browser.cmd`. It must pass package integrity, DF_Medium provenance, WPF compilation, the historical 8.1.x/8.2.x regression gates, 9.0.0 Optical Instrument markers, WebView2 managed binding, Windows archive preflight, all four VEC1 node-container bindings, and the 12,500-work-item traceability gate.
3. Run `Install Live Web Bridge.cmd` while online if the adapter is not already provisioned. It must provision/check Microsoft WebView2 SDK adapter 1.0.4191.47, validate managed assembly identities, explicitly load Core then WPF, and report whether the Evergreen WebView2 Runtime is discoverable.
4. Launch **JA21 Virtual Browser** from the installed Desktop icon. The shell must open as the 9.0.0 **Optical Instrument** experience: full-bleed content plane, floating command rail, floating spatial tab rail, compact trust pill, and one JA21 action bubble rather than permanent conventional toolbar/status rows.
5. Confirm LIVE web uses `WebView2CompositionControl`, not the legacy WPF `WebView2` HwndHost surface. Open Ctrl+K and the Context/VEC1 drawer over a live website and verify both render above and interact above the website without disappearing behind the web surface.
6. Confirm the LIVE/NATIVE segmented renderer instrument reflects actual renderer state. LIVE must be disabled/unavailable when the adapter/runtime cannot initialize; NATIVE must remain usable as DF_Medium inspection mode.
7. Open a modern JavaScript-heavy video site in LIVE. Verify the page, controls, adaptive playback and normal site interaction remain inside the same JA21 omni window rather than opening an external browser.
8. Activate the site's HTML fullscreen video control. JA21 must withdraw command rail, tabs, load sweep, trust/status surfaces, floating bubble, shell edge treatment and transient drawers; WebView2 must occupy the current monitor full-bleed. Exiting site fullscreen must restore the prior optical shell state.
9. Press F11 manually and verify the same immersive withdrawal/restore behavior. Move the JA21 window to another monitor before entering fullscreen and confirm the monitor containing JA21 is used rather than the primary monitor.
10. Press Ctrl+K. The command palette must open in-window above LIVE content, support keyboard-only selection, Escape dismissal/focus recovery, and actions for new/private tab, LIVE/NATIVE, diagnostics, downloads, immersive mode and omni focus.
11. Open Context/VEC1. The contextual drawer must remain inside the JA21 window, originate from the optical shell, support progressive disclosure, and close before page navigation when Escape is used.
12. Verify root-level Escape priority: command palette → contextual drawer → omni panel → application immersive mode. Site-owned fullscreen must retain its own expected Escape behavior.
13. Verify Ctrl+Tab and Ctrl+Shift+Tab cycle tabs deterministically. Verify Ctrl+T, Ctrl+W, Ctrl+R, Ctrl+L, Ctrl+Shift+N, Alt+Left and Alt+Right remain functional.
14. Inspect hairline geometry at 100%, 125%, 150%, 175%, 200%, 250% and 300% Windows scaling where available. Structural rules should remain approximately one physical pixel, not one fixed DIP, with no alternating blur/thickness while moving between mixed-DPI monitors.
15. Verify the default light optical theme, `JA21_THEME=dark` override, and Windows High Contrast behavior. Functional separation must not depend solely on blur/transparency, and focus indicators must remain legible over bright pages and dark video.
16. Set `JA21_REDUCED_MOTION=1`. Re-run palette, drawer, tab selection, renderer switch and immersive transitions. Nonessential spring/translation motion must reduce/snap while state changes remain understandable.
17. Use keyboard-only navigation through browser-owned controls and verify deterministic focus restoration after closing the command palette and drawer. Run a screen-reader/UI Automation inspection and confirm meaningful names/states on the omni input, renderer instrument, trust surface, command palette and essential controls.
18. Verify normal WebView2 profile/cache state is under `%LOCALAPPDATA%\VBJA21\9.0.0\live-web` unless `JA21_WEB_DATA_ROOT` explicitly overrides it. Create a private tab, browse, close it and confirm the dedicated ephemeral profile is disposed/deleted.
19. Confirm camera/microphone/geolocation/notification escalation is denied by default. `JA21_ALLOW_WEB_PERMISSIONS=1` is the explicit opt-in boundary. Verify browser trust indicators remain distinguishable from website-rendered content.
20. Type `http://127.0.0.1/` and `http://169.254.169.254/`; both must be refused unless `JA21_ALLOW_PRIVATE_HOSTS=1` is deliberately set. LIVE top-level redirects must be rechecked against the same boundary.
21. Verify back, forward, reload/stop and data-clear semantics route to WebView2 in LIVE and to the bounded JA21/DF_Medium path in NATIVE. Switching renderers must not silently claim success if the target renderer did not initialize.
22. Run `Audit VEC1 Electrons.cmd` after closing the browser. Presenter-written electron state and ledgers must verify. Presentation records may identify `webview2-live` or `df-medium-native`; `fabric_verdict` must remain null unless an authoritative control-plane verification records it.
23. Run the independent VEC1 control-plane suite. The presenter must never synthesize `EXECUTION_VERIFIED` or cross-node agreement from UI readiness, renderer readiness or node availability.
24. Run ETW/WPF performance capture for cold launch, warm launch, palette open/close, drawer open/close, tab switch, renderer switch, resize and fullscreen entry/exit. Record UI-thread stalls, frame pacing, memory growth, GPU/composition work and leaked browser processes/handles.
25. Stress the shell with repeated palette/drawer toggles, 100+ tab create/close cycles, renderer switches, window resizes and fullscreen transitions. Confirm no unbounded memory/process/handle growth and no stale overlay/focus state.
26. Qualify on integrated graphics and, where available, a discrete GPU. Test Windows transparency enabled/disabled and hardware acceleration fallback. Record any material downgrade rather than treating a fallback as a visual PASS.
27. Where available, test SDR/HDR, protected-media/DRM video and high-refresh-rate playback. Record these as environment-specific results; do not infer universal codec/DRM compatibility from ordinary video playback.
28. Open `evidence/OPTICAL-INSTRUMENT-WORKITEM-TRACEABILITY-9.0.0.jsonl` and confirm 12,500 unique work-item records from `1.01.01` through `20.25.25`. Windows-only visual/performance/compatibility/closeout dispositions remain pending until this checklist produces evidence.
29. Confirm `electron.exe`, `node.exe`, `chrome_elf.dll` and a bundled `msedgewebview2.exe` are absent. LIVE uses the separately installed WebView2 Runtime; VEC1 remains the application lifecycle/state substrate rather than Electron/Node.
30. Archive the verification log, screenshots, DPI/monitor matrix, screen-reader evidence, ETW/performance traces, video/fullscreen results and any failures as the 9.0.0 target qualification record before promoting the build as Windows-qualified.

## Qualification boundary

This checklist qualifies the **9.0.0 JA21 Optical Instrument integration on the tested Windows target(s)**. Cross-platform/static verification proves package consistency and many implementation invariants, but it does not substitute for real WPF compilation, `WebView2CompositionControl` airspace behavior, mixed-DPI visuals, screen-reader interaction, GPU/compositor performance, HDR, protected-media/DRM or site-specific playback qualification. LIVE delegates modern HTML/CSS/JavaScript/media execution to the installed WebView2 Runtime; NATIVE remains the bounded DF_Medium JA21 inspection profile.
