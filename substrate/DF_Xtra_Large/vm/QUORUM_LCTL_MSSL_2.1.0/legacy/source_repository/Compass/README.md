## Corpus-native design

The scripts use only patterns demonstrated by the corpus:

- `deepml logic 0.3`
- pure-by-default and no-network policies
- immutable values
- pure scoring predicates and functions
- knowledge bases, facts, predicates, and rules
- recursive feasibility-path inference
- tabled and best-first evaluation
- planning declarations
- proof-carrying certification
- rule indexing, common-subexpression elimination, tabling, and proof normalization
- lowering to `DEEPML_LOGIC_R12`

## Repository behavior

### Direction
Scores and admits candidate directions only when their policy and evidence gates are ready.

### Priorities
Classifies critical and high priorities, checks dependencies, and releases only suite-approved work.

### Policies
Requires every permitted action to satisfy the complete policy set rather than relying on an implicit default.

### Feasibility paths
Builds recursive paths from individually feasible edges and supports best-first, memoized search.

### Routing objectives
Selects routes only when they satisfy policy, evidence, feasibility, priority alignment, and minimum-change objectives.

## Configuration boundary

The embedded facts are deterministic starter records and should be replaced with repository-specific facts. Several suite-approval predicates are intentionally left as integration hooks so SOPHIA, CHARLOTTE, LANDON, Professor, and Podium can supply their own judgments and evidence.

## Validation boundary

All five scripts passed structural token and delimiter checks against corpus-demonstrated forms. They were not compiled or executed because no production-certified DeepML Logic compiler/runtime was included with the attachment.
