## 2. Purpose and Boundary

Suite 65 is the deterministic execution kernel for the complete suite repository. It does not replace:

- **Suite 56**, which owns queues, workers, and sandbox resources;
- **Suite 60**, which owns individual approved worker execution;
- **Suite 62**, which exposes LANDON Run and Run All;
- **Suite 63**, which supplies the sandbox and offline runtime environment.

Suite 65 binds those components into one governed lifecycle. It owns the run contract, state transitions, isolation policy, capability checks, evidence requirements, validation gates, recovery behavior, and publication decision.

The engine is:

- no-autorun;
- default-deny;
- repository-confined;
- deterministic for identical pinned inputs and policy;
- offline by default;
- capability-gated;
- resource-bounded;
- idempotent at the run and job levels;
- fully observable;
- review-before-publish;
- rollback-capable;
- accepted-feedback-only for learning promotion.

## 3. Separation of Duties

| Component | Binding responsibility | May do | Must not do |
|---|---|---|---|
| SOPHIA | Observe, understand, reason, evaluate, and learn | Evaluate feasibility, policies, outputs, evidence, and accepted feedback | Execute jobs, grant authority, or promote rejected feedback |
| CHARLOTTE | Construct, render, inspect, and improve | Build staged artifacts, previews, scenes, render plans, and review findings | Bypass Podium authorization or publish unreviewed changes |
| LANDON | Author, control, review, and integrate | Display state, govern runs, review proposals, integrate approved outputs | Conceal evidence, silently widen scope, or bypass approval |
| Professor | Explain and propose | Explain architecture, produce plans, reviews, and action cards | Silently execute commands or modify repository files |
| Podium | Authorize, route, schedule, and recover | Validate action cards, authorize bounded work, schedule jobs, invoke recovery | Create undeclared authority or approve an incomplete contract |
| HERMIT | Execute inside isolation | Run the exact authorized job with the exact capability set | Expand scope, alter policy, authorize itself, or publish directly |

Binding control sequence:

> Professor proposes. Podium authorizes and schedules. HERMIT executes. LANDON displays and governs. SOPHIA evaluates. CHARLOTTE constructs and inspects.

## 4. Canonical State Machine

```text
DRAFT
  -> PROPOSED
  -> AUTHORIZED
  -> QUEUED
  -> STAGING
  -> READY
  -> RUNNING
  -> VALIDATING
  -> REVIEW_REQUIRED
  -> APPROVED
  -> PUBLISHED

Any active state may transition to:
  -> PAUSED
  -> CANCELLED
  -> FAILED
  -> RECOVERING
  -> ROLLED_BACK
  -> QUARANTINED
```

Rules:

1. `DRAFT -> PROPOSED` requires a complete Professor action card.
2. `PROPOSED -> AUTHORIZED` requires Podium policy approval and a human approval when the action card declares one.
3. `AUTHORIZED -> QUEUED` requires a resolved suite route, capability manifest, resource budget, input hashes, and idempotency key.
4. `STAGING -> READY` requires immutable input capture, repository confinement, and a clean execution-cell attestation.
5. `RUNNING -> VALIDATING` requires a terminal worker result with stdout, stderr, exit code, timestamps, and output inventory.
6. `VALIDATING -> REVIEW_REQUIRED` requires all mandatory validation suites to finish.
7. `REVIEW_REQUIRED -> APPROVED` requires the configured human or policy review.
8. Only `APPROVED` may transition to `PUBLISHED`.
9. A failed safety, security, provenance, or output-validation gate transitions to `QUARANTINED`, not `PUBLISHED`.
10. Recovery never reuses a mutable execution cell.

## 5. Canonical Run Contract

Every execution begins with one immutable `SandboxRunContract`.

| Field | Type | Required | Rule |
|---|---|---:|---|
| `run_id` | identifier | yes | Unique and immutable |
| `idempotency_key` | string | yes | Same key and same contract resolve to the same run |
| `requested_by` | principal | yes | Must resolve to an authorized local identity |
| `created_at` | timestamp | yes | UTC, monotonic ordering preserved |
| `intent` | text | yes | Human-readable bounded objective |
| `job_family` | enum | yes | One approved family only unless `run_all` is authorized |
| `entry_suite` | suite reference | yes | Must resolve in the suite registry |
| `inputs` | artifact references | yes | Content-addressed and immutable for the run |
| `repository_root` | confined path | yes | Cannot escape the approved worktree |
| `output_contract` | schema reference | yes | Declares formats, locations, limits, and validators |
| `capabilities` | capability set | yes | Explicit allow-list; empty is valid |
| `network_policy` | enum | yes | `deny`, `allowlisted`, or `explicit_session` |
| `resource_budget` | budget | yes | CPU, memory, storage, wall time, and output limits |
| `retry_policy` | bounded policy | yes | Finite attempts and backoff |
| `approval_policy` | policy reference | yes | Declares human and automated gates |
| `release_policy` | policy reference | yes | `evidence_only`, `reviewed_artifacts`, or `release_candidate` |
| `expected_hashes` | hash set | no | Required when inputs or tools are pre-pinned |
| `locale` | locale tag | yes | Default presentation and diagnostic locale |
| `accessibility_profile` | profile reference | yes | Required for user-facing output |

Contract invariants:

- no undeclared input;
- no undeclared output path;
- no ambient network;
- no unrestricted shell;
- no mutable source input;
- no infinite retry;
- no unbounded recursion, queue fan-out, memory, storage, or wall time;
- no publication without evidence and review;
- no learning promotion without accepted, verified feedback.

```ja21
    }

    proposal {
        action_card = SE_31.PROFESSOR.propose(contract)

        require action_card.fields {
            intent
            scope
            capability_contract
            parameters
            preconditions
            expected_effects
            impact
            risks
            evidence
            rollback
            unified_diff_when_applicable
            hashes
            approval_requirements
        }

        emit state.PROPOSED
    }

    authorization {
        decision = SE_32.PODIUM.authorize(
            action_card,
            SE_06.capability_manifest,
            SE_07.approval_policy,
            SE_08.safety_report,
            SE_09.network_policy,
            SE_10.resource_reservation
        )

        if decision != APPROVED {
            quarantine(reason = decision.reason)
            stop
        }

        emit state.AUTHORIZED
    }

    stage {
        workspace = SE_04.create_confined_workspace(
            repository_snapshot = SE_03.snapshot,
            read_only_inputs     = contract.inputs,
            output_contract      = contract.output_contract
        )

        cell = SE_13.create_disposable_cell(
            workspace     = workspace,
            capabilities  = SE_06.capability_manifest,
            network       = SE_09.network_policy,
            resources     = SE_10.resource_reservation
        )

        assert cell.clean_attestation == PASS
        emit state.READY
    }

    dispatch {
        job_graph = SE_14.route(
            job_family  = contract.job_family,
            entry_suite = contract.entry_suite,
            registry    = SE_05.registry
        )

        jobs = SE_11.enqueue_idempotent(
            graph           = job_graph,
            idempotency_key = contract.idempotency_key
        )

        workers = SE_12.bind_healthy_workers(jobs)
        SE_32.PODIUM.schedule(jobs, workers, cell)
        emit state.QUEUED
    }

    execute {
        emit state.RUNNING

        for job in SE_11.deterministic_order {
            require SE_32.authorization_covers(job)
            require SE_06.capabilities_cover(job)
            require SE_10.budget_remaining(job)

            result = SE_13.HERMIT.execute_exact(job)

            SE_25.capture {
                job.request
                job.worker_identity
                job.tool_versions
                job.started_at
                job.finished_at
                result.stdout
                result.stderr
                result.exit_code
                result.resource_use
                result.outputs
            }

            if result.failed {
                SE_26.handle_bounded_failure(job, result)
            }

            SE_27.checkpoint(job, result)
        }
    }

    evaluate {
        emit state.VALIDATING

        validation = SE_17.run {
            positive
            negative
            boundary
            security
            regression
            release
        }

        SOPHIA_evaluation = SE_33.SOPHIA.evaluate(
            contract,
            SE_25.events,
            SE_27.provenance,
            validation
        )

        CHARLOTTE_review = SE_34.CHARLOTTE.inspect(
            outputs = SE_27.current_artifacts
        )

        require CHARLOTTE_review.labels {
            Approve
            Reject
            Risk
            Unified_diff
        }

        if any_required_gate_failed {
            quarantine(evidence = validation)
            stop
        }

        emit state.REVIEW_REQUIRED
    }

    review_and_publish {
        review = SE_30.LANDON.present_for_review(
            action_card,
            SE_25.diagnostics,
            SE_28.diff,
            SOPHIA_evaluation,
            CHARLOTTE_review,
            SE_36.compatibility_report
        )

        if review != APPROVED {
            SE_26.rollback_to_last_verified_checkpoint()
            emit state.ROLLED_BACK
            stop
        }

        emit state.APPROVED

        if contract.release_policy == evidence_only {
            SE_27.file_evidence_only()
        }

        if contract.release_policy == reviewed_artifacts {
            SE_28.apply_approved_patch_or_artifacts()
        }

        if contract.release_policy == release_candidate {
            SE_29.certify_and_package()
        }

        SE_27.archive_canonical_run()
        SE_36.emit_json_compatibility_report()
        emit state.PUBLISHED
    }

    finally {
        SE_13.destroy_execution_cell()
        SE_10.release_resources()
        SE_25.flush_logs()
        SE_27.seal_manifest()
    }
}
```

## 10. Run All Semantics

`Run All` is not unrestricted fan-out. It expands only the suites explicitly selected in the approved action card.

```ja21
procedure run_all(selected_suites[]) {
    require selected_suites not_empty
    require selected_suites subset_of SE_05.registry
    require SE_32.authorization.exactly_covers(selected_suites)

    graph = SE_05.build_dependency_graph(selected_suites)
    graph = SE_05.reject_cycles_or_apply_declared_cycle_policy(graph)
    waves = graph.topological_execution_waves()

    for wave in waves {
        SE_10.assert_wave_budget(wave)
        SE_11.enqueue_deterministic(wave)
        execute wave with bounded_parallelism
        validate wave

        if wave.required_job_failed {
            SE_26.stop_dependents()
            SE_26.recover_or_rollback()
            break
        }
    }

    SE_36.synthesize_run_all_report()
}
```

Deterministic fan-in uses:

1. declared dependency order;
2. suite number;
3. sub-suite ID;
4. job ID;
5. artifact logical name;
6. content hash as the final stable tie-breaker.

## 11. Capability Model

Allowed capability families:

| Capability | Default | Scope rule |
|---|---|---|
| `repository.read` | denied | Explicit confined paths |
| `repository.write_staging` | denied | Staging worktree only |
| `repository.apply_patch` | denied | Approved unified diff only |
| `process.execute` | denied | Approved executable and argument template |
| `shell.approved_command` | denied | Command-policy allow-list only |
| `network.connect` | denied | Endpoint, protocol, purpose, and deadline required |
| `archive.read` | denied | Bounded depth, size, entry count, and path validation |
| `artifact.write` | denied | Declared output roots and types only |
| `model.invoke` | denied | Approved local provider, model hash, and budget |
| `renderer.invoke` | denied | Approved renderer and output contract |
| `package.create` | denied | Approved format and release policy |
| `signing.prepare` | denied | Preparation only unless signing authority is separately granted |
| `learning.record` | denied | Evidence record only |
| `learning.promote` | denied | Verified, accepted Professor feedback only |

Capability expansion after authorization is forbidden. A wider requirement generates a new action card and a new authorization decision.

## 12. Isolation and Path Policy

The execution cell exposes only:

```text
/run/contract/      read-only normalized contract
/run/input/         read-only content-addressed inputs
/run/repository/    confined staged worktree
/run/output/        declared artifact roots
/run/temp/          quota-bound disposable scratch
/run/evidence/      append-only event and provenance records
```

Rejected paths include:

- absolute host paths not mapped by the contract;
- parent traversal;
- unresolved symlink or junction escapes;
- device files;
- alternate data streams not declared by policy;
- archive entries that normalize outside the extraction root;
- writes to input mounts;
- writes outside declared output or staging roots.

## 13. Failure, Retry, and Recovery Policy

| Failure class | Default behavior | Retry eligibility |
|---|---|---|
| Contract invalid | Reject before authorization | No |
| Approval absent | Pause in `PROPOSED` | No automatic retry |
| Capability denied | Quarantine | New action card required |
| Static safety failure | Quarantine | After corrected inputs only |
| Worker unavailable | Rebind healthy approved worker | Yes, bounded |
| Resource budget exceeded | Terminate cell and preserve evidence | Only with new authorization |
| Deadline exceeded | Terminate cell and preserve checkpoint | Yes, if contract allows |
| Tool crash | Replace cell and retry from verified checkpoint | Yes, bounded |
| Output schema failure | Preserve outputs as quarantined evidence | Corrective pass if authorized |
| Hash mismatch | Quarantine and invalidate affected descendants | No automatic retry |
| Security or injection finding | Stop affected branch and quarantine | New reviewed contract required |
| Review rejected | Roll back or retain evidence only | New proposal required |
| Packaging failure | Preserve reviewed artifacts; do not release | Yes, bounded |

Retry rules:

- attempts are finite;
- every attempt receives a new cell ID;
- the same job ID is retained with an incremented attempt number;
- prior stdout, stderr, exit code, resource use, and artifacts remain immutable;
- non-idempotent jobs require an explicit compensating action;
- retry never widens capabilities or budgets.

## 14. Validation and Release Gates

### Positive suite

- valid contract reaches `REVIEW_REQUIRED`;
- approved deterministic job produces the declared artifacts;
- identical pinned inputs reproduce identical normalized records and hashes;
- Run All honors dependency order and bounded parallelism.

### Negative suite

- incomplete contract is rejected;
- undeclared command, path, endpoint, output, or model is denied;
- Professor cannot dispatch;
- HERMIT cannot self-authorize;
- unreviewed output cannot publish.

### Boundary suite

- maximum accepted input count;
- maximum archive depth and expanded size;
- maximum large-file window;
- CPU, memory, storage, process, log, and wall-time limits;
- retry and correction iteration ceilings;
- empty capability manifest and zero-network execution.

### Security suite

- path traversal, symlink, junction, archive, and command-injection defense;
- prompt-injection and malicious repository-content defense;
- capability-confusion and confused-deputy defense;
- hash and signature verification;
- secret redaction from logs and diagnostics;
- network-deny enforcement and allow-list expiry;
- output validation before publication.

### Release suite

- clean state history;
- complete hashes and provenance;
- all mandatory tests pass;
- review labels are present;
- rollback record exists;
- installer and air-gap evidence pass when applicable;
- final JSON compatibility report validates against its schema.
