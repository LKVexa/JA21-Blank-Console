# QUORUM RC-PW 7.0.0 — Traceability and Evidence Contract

## Requirement traceability

Every requirement must map:

`requirement → semantic clause → source file/function/row → test vector → execution command → exit code → runtime evidence → digest → gate → qualification profile`

## Evidence rules

- Evidence must be generated by the current modified repository/build.
- Expected-output fixtures may define expectations but cannot substitute for observed execution.
- Logs must include tool/runtime versions and profile.
- Deterministic replay must compare canonical state digests at fixed checkpoints.
- Performance evidence must identify hardware/runtime, sample interval, warmup, duration, population/scene load, and percentile metrics.
- A failing required test cannot be offset by unrelated passing tests.
- Unknown or unavailable evidence is BLOCKED, not PASS.

## Promotion artifacts

Each release must include:
- build/source manifest;
- SHA-256 source/evidence list;
- requirements catalog;
- gate matrix;
- risk register;
- rollback plan;
- exact command transcript;
- deterministic replay digests;
- benchmark/resource profile;
- unresolved blockers.
