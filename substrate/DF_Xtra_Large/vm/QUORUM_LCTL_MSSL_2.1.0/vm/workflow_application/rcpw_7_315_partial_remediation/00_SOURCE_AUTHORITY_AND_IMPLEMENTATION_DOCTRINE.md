# QUORUM Source Authority and Implementation Doctrine

Use the repository's established authority chain:

1. **MSSL semantic contracts/invariants** for state meaning, authority, lifecycle, failures, and evidence obligations.
2. **Schemas/manifests/evidence registries** for machine-checkable structure.
3. **Columned LCTL editable execution source** where the requirement belongs in native guest behavior.
4. **Canonical lowered/verifier-passing LCTL** as executable language authority.
5. **Hosted VM world services** for the currently declared hosted RC-PW service layer.
6. **Fresh executable evidence** from tests, replays, benchmarks, fault injection, and qualification.
7. **Documentation** as explanation only.

When the Columned LCTL/MSSL corpora are available, use them as writing/source-form guides; do not replace the actual target repository's established semantics with examples from the corpora.

## Anti-shortcut rules

- no documentation-only PASS;
- no mock/stub/TODO PASS;
- no expected-output file substituted for observed output;
- no keyword-based promotion;
- no lower-profile evidence promoted to a higher profile;
- no renderer-only fact becomes canonical truth;
- no fold/LOD optimization mutates canonical identity/topology/history;
- no unsupported 8S/Penteract term controls canonical state.
