# QUORUM hard-open policy applied to QVM

The Track A and SHS packages are used as governance overlays: current-root evidence only, required skip equals failure, no manual override, deterministic fail-closed behavior, traceability from source to build to test to evidence, and no promotion from planning artifacts alone.

JA21 self-hosting, native MSSL runtime, UEFI/OS construction, physical hardware qualification, and other scope-specific predicates are not silently relabeled as VM achievements. Where a source workflow requires those external or different-project predicates, the QVM application ledger records them as `BLOCKED` or `NOT_APPLICABLE` with a reason.
